- 고정 커밋: `d706ad2ea66aaed6faeebea1c21dc358ace0ecf2`.
- 이번 실생성 시도: **0회**, Gemini 요청: **0회**. 프로세스·사용자·시스템 환경변수와 새 작업 사본에 키가 없습니다. 모델 접근 권한·쿼터는 확인하지 못했습니다.

## 2. 새 컴퓨터에서 안전하게 준비하기

기존 팀 프로젝트 폴더 밖에서 PowerShell을 여세요. 아래에서는 `task3-lab`이라는 **새 폴더**를 사용합니다. 이미 같은 이름의 폴더가 있으면 다른 이름으로 바꾸세요.

```powershell
New-Item -ItemType Directory task3-lab
Set-Location task3-lab
git clone --single-branch --branch iteration-1-demo https://github.com/snuhcs-course/swpp-2026-project-team-02.git source
git -C source switch --detach d706ad2ea66aaed6faeebea1c21dc358ace0ecf2
git -C source rev-parse HEAD
git -C source status --short
python --version
python -m venv --without-pip .venv
```

`clone`은 사본을 받는 작업입니다. `switch --detach`는 그 사본을 조사한 버전에 고정합니다. `status`에 아무것도 나오지 않으면 추적되는 팀 파일이 바뀌지 않은 상태입니다. 이 작업에는 commit, merge, push가 필요 없습니다. 별도 사본에서만 진행하세요.

Python 3.13.15에서 이번 검사를 수행했습니다. 다른 버전은 이번에 검증하지 않았습니다. backend가 외부 패키지를 요구하지 않아 pip 설치 없이 환경을 만들었습니다. 이 장비에서는 Python 경로 경고가 있었지만 실행과 검사는 진행됐습니다.

제출물 `task3` 폴더를 `task3-lab/task3`에 복사하세요. 다음 명령은 `task3-lab`에서 실행합니다.

```powershell
.\.venv\Scripts\python.exe task3/test_metrics.py
.\.venv\Scripts\python.exe task3/task3_measure.py --repo source --mode offline --out results-offline-01
.\.venv\Scripts\python.exe task3/offline_probes.py --repo source --out results-scripted-01
```

결과 폴더가 이미 있으면 덮어쓰지 않고 종료합니다. 다른 폴더 이름을 사용하세요. standalone 실행기가 임시 로컬 HTTP 서버를 시작하고 종료하므로 `api_server.py`를 따로 켤 필요가 없습니다. 방화벽/실행 제한 때문에 localhost 연결이 막히면 해당 환경의 실행 권한이 필요합니다. 네트워크 실패를 계획 생성 실패로 해석하지 마세요.

계획 생성 기존 테스트는 13개 중 12개 통과, 1개 실패가 현재 기준입니다. 실패 로그에 `document["weekly_availability"]` 비교가 나오면 저장 과정의 7요일 정규화와 기대값 2요일의 불일치인지 확인하세요. 다른 실패는 별도로 조사해야 합니다.

## 3. 키가 준비된 경우 실생성

키를 채팅에 붙여 넣지 마세요. 이 PowerShell에서만 환경변수로 입력하는 방법입니다. 입력 내용은 화면과 명령 기록에 나타나지 않습니다.

```powershell
$task3SecureKey = Read-Host 'Gemini API 키' -AsSecureString
$task3Credential = [pscredential]::new('task3', $task3SecureKey)
$env:GEMINI_API_KEY = $task3Credential.GetNetworkCredential().Password
```

먼저 1케이스 1회로 인증·모델·응답 형식을 확인합니다. 조사 커밋의 모델은 `gemini-3.5-flash-lite`입니다. 사용 가능한 다른 모델로 자동 변경하지 않습니다.

```powershell
.\.venv\Scripts\python.exe task3/task3_measure.py --repo source --mode live --case-id license_planner_case_01_beginner_weak_charts --repeats 1 --out results-live-smoke-01
```

성공하면 `runs.csv`의 HTTP 200, `constraint_valid=True`, 원본 응답과 과목 통계를 확인한 뒤 반복 실험을 진행합니다.

```powershell
.\.venv\Scripts\python.exe task3/task3_measure.py --repo source --mode live --repeats 5 --out results-live-17x5-01
```

전체 17케이스×5회는 계획 생성 **85건**입니다. 한 생성이 여러 Gemini 요청을 보낼 수 있습니다. 여기에 smoke 1건은 별도이며 반복 집계에 자동 합치지 않습니다. 예산이 적으면 `--case-id`를 여러 번 지정해 기존 4케이스부터 진행하세요. seed로 실행 순서를 섞어 순서 효과를 줄이지만 Gemini 결과를 결정적으로 고정하지는 않습니다. 같은 입력의 5회는 탐색적 검증이며 통계적 확증이 아닙니다.

인증·모델 없음·쿼터 오류(401/403/404/429 등)가 나오면 이후 예정 건은 skipped로 기록합니다. 자동 재시도와 모델 대체는 하지 않습니다. 키가 없으면 모든 건이 skipped이며 실패율은 N/A입니다. 실패한 HTTP 요청을 공부량 0인 성공 계획으로 바꾸지 않습니다.

끝나면 환경변수와 임시 자격증명 변수를 제거합니다.

```powershell
Remove-Item Env:GEMINI_API_KEY
Remove-Variable task3SecureKey,task3Credential
git -C source status --short
```

## 4. 결과 파일 읽기

| 파일 | 내용 |
|---|---|
| `manifest.json` | 커밋·모델·시각(KST)·Python/OS·키 존재 여부·입력 해시·측정 범위 |
| `cases_used.json` | 해당 실행의 입력 원본과 고정 평가 과목 분류 |
| `*-raw.json` | 요청·응답·도구 인자/반환값·도구/모델 호출 시간·HTTP 기록. 키 문자열은 제거하여 저장 |
| `*-schedule.csv` | 성공 응답의 공부/외부 일정 |
| `*-windows.csv` | 날짜별 시간창의 가용 분수·실제 공부 분수·비율 |
| `*-topics.csv` | **채택된 일정 생성 시점**의 모델 분류에 따른 과목별 배점·정답률·공부 분수 |
| `*-fixed-topics.csv` | 모델 분류와 독립된 실험 fixture 분류로 계산한 과목 통계 |
| `runs.csv` | 개별 반복 결과. N/A는 빈 셀이며 0이 아님 |
| `summary.csv` | 케이스별 시도/성공/skipped, 실패율, 성공 결과 지표의 평균·반복 간 모집단 표준편차·최솟값/최댓값·유효 n |
| `execution_summary.json` | 실제 생성 시도 건수와 중단 사유 |
| `repository_check.json` | 실행 후 추적 파일 변경 여부 |

`time_ratio_population_std`는 **한 계획 안의 시간창 비율 편차**입니다. `*_repeat_std`는 **반복 실행 사이의 편차**입니다. 둘을 혼동하지 마세요. 비율 단위 값에 100을 곱하면 퍼센트포인트입니다. 과목 정답률과 공부 분수의 Pearson은 보통 음수를 기대하며, 점수나 분수의 분산이 0이면 N/A입니다. 이때는 `pearson_na_reason`을 확인하세요.

실패율의 분모는 skipped를 제외한 실제 HTTP/전송 시도입니다. 측정 오류는 별도 열에 기록됩니다. HTTP 성공이지만 제약 위반인 계획은 `constraint_invalid_success`에 별도로 남습니다. 지표 평균은 HTTP 성공·측정 성공 결과 기준이므로 유효 계획만 따로 분석하려면 `constraint_valid`로 거르세요. 과목 3개에서 계산한 r을 사용자 전체에 일반화하지 마세요.

생성 시간은 서버 시작을 제외한 로컬 HTTP 왕복 시간이며 Gemini·도구 계산·CSV 저장을 포함합니다. 실패 요청 시간은 `all_attempt_latency_mean`에 포함되고 성공 시간과 구분됩니다. 120초 초과 건수는 앱 제한과 비교할 단서이며 앱에서 실제 시간초과를 확인한 결과는 아닙니다.

API가 공부 CSV를 사본의 `source/backend/license_planner/output/`에도 저장합니다. 100개 초과 시 오래된 자동 저장 파일을 정리하는 기존 동작이 있으므로 제출 원본은 별도 결과 폴더로 삼으세요. 실행기는 팀의 추적 파일을 수정하지 않지만 실행 과정에서 무시된 캐시·자동 출력 파일이 생길 수 있습니다.

## 5. 팀 전달 전 확인

`보고서.md`의 Live 결과 N/A를 **실제로 얻은 runs/summary CSV로만** 갱신하세요. `실측_상태.csv`는 현재 실생성 미수행을 표시하는 파일이며 향후 결과 파일로 덮어 쓰지 않습니다. scripted 검사값을 Live 표에 옮기지 마세요. 실험용 15문항은 정답·분류·난이도 검토를 거쳐야 하며 제품 문제은행에 자동 반영하면 안 됩니다.
