# 복습 시간 이상의 취약 토픽 추가량과 실제 A/B 비교

검증 정리: 2026-11-29 (Asia/Seoul), `fix/reassessment-session-allocation`. 기본 실제 A/B 입력과 실행 결과, Windows·Linux 백엔드 및 Windows JDK 25 Android 재평가 테스트 결과를 포함한다.

## 유지한 세 조건과 보완한 배분

기존 고득점 경계 `min(자격증 합격 점수 + 10, 100)` 및 세 조건은 유지한다. 고득점이면서 잔여 비율 >=95% 또는 유효한 실제 학습 보고 합 <=10분이면 에이전트가 정한 1회 복습(최소 15분)으로 감축한다. 두 조건 모두 미충족인 고득점 토픽은 0분까지 감축 가능하다. 미보고는 0분 보고와 다르다.

취약 토픽은 경계 미만이며, 각 토픽에 에이전트가 최종 미래 분량·1회 복습 예상 시간·개별 근거를 제안한다. 입력에는 진단 점수, 원본 전체 및 변경 가능 잔여 분량, 보고한 실제 학습, 완료 처리된 계획량, 미충족 계획량을 제공한다. 이제 미보고의 실제 학습 값은 null로 전달하고 명시적 Missed는 0으로 구분한다. 근거는 데이터와 연결하도록 지시하되 자유 서술 전체의 사실성이나 학습 효과의 최적성을 증명했다고 주장하지 않는다.

취약 토픽의 최종 총량에서 원본 취약 토픽 잔여 총량을 뺀 값이 순추가 시간 E다. E>0이면:

- 각 취약 토픽의 추가량(최종−원본 잔여)은 에이전트가 선택한 해당 토픽의 **1회 복습 시간 이상**이어야 한다. 최소 길이는 15분이다.
- 전체 최소안이 기존 구간·보호 일정·총시간 내에 배치 가능한지, 각 토픽에 복습 길이의 연속 구간이 있는지 별도 탐색한다.
- 전체 최소안이 물리적으로 불가능하다고 증명되면 15분 최소안을 검사한다. 이 대안도 불가능하면 제안을 거절한다. 실제 배정은 15분보다 커도 된다.
- 탐색 노드/재귀 한도 초과는 가능성 미확인이다. 이를 불가능 증명이나 15분 대안의 근거로 사용하지 않는다. 모델의 합산·짧은 조각·정확한 예산 배치 오류도 물리적 불가능의 근거가 아니다.
- 편중을 막기 위해 토픽 추가량 상한은 `max(해당 최소량, ceil(1.5 × E / 취약 토픽 수))`로 둔다. 한 토픽이면 상한은 E다. 1.5는 이번 알파의 운영 기준이며 학습 효과로 보정된 최적값은 아니다.

E<=0이면 추가할 순시간이 없으므로 기존 취약 토픽 포함 검사를 유지한다. 위 규칙은 점수 비율로 실제 배분을 계산하는 대체 함수가 아니다. 범위 안에서 점수·학습 이력·잔여량을 고려한 구체적인 분량은 에이전트가 정한다.

## 에이전트 결정과 물리적 배치의 구분

기존 시간대별 제안 도구에 더해 `propose_topic_budgets`를 제공한다. 모델이 모든 토픽의 정확한 미래 총량과 복습 예상량을 선택하고 백엔드가 그 분량을 기존 구간에 배치한다. 모델 분량을 다른 분량으로 바꾸는 fallback은 없다. 배치할 수 없는 정확한 예산이면 모델에 수정 요청한다.

최소안 가능성 검사는 하한/상한·기존 구간·최소 조각·고득점 복습 1회 연속성·취약 토픽 복습 길이의 연속 구간을 고려하는 유한 탐색이다. 탐색을 마쳐 해가 없을 때만 불가능으로 판정한다. 실제 예산 배치와 최소안 가능성 검사는 다르므로, 특정 예산 배치 실패만으로 최소 복습량을 낮추지 않는다. 원래의 짧은 구간은 더 나누지 않는다.

정책 버전은 `review-sized-weak-additions-v5`다. 문맥은 미리보기 서명에 포함되며 도구 trace에 원본 모델 제안, 검증된 배치와 최소량/15분 대안 판정을 기록한다. 저장 시 모델을 다시 호출하지 않는다.

## 동일 입력 실제 A/B 비교

실제 생성 체크포인트와 기본 기록을 그대로 사용했다. 이전 v3 실행과 원본 행·생성 입력·보고·기준 시각·A/B 진단 입력이 같음을 비교했다. 원본 전체 960분 중 과거·진행 중 360분을 고정하고 미래 600분만 재배분한다. 매크로는 실제 보고 140분이고 다른 토픽은 미보고다.

모델은 실제 `google/gemini-2.5-flash`다. 아래 점수는 A/B 순이며, 모든 시간은 분이다. 이전은 사용자가 확인한 v3 실제 실행, 수정 후는 v5 새 실제 실행이다.

| 토픽 | 원본 전체 | 원본 잔여 | A/B 점수 | A 이전→수정 후 | B 이전→수정 후 |
| --- | ---: | ---: | --- | ---: | ---: |
| 매크로 활용 | 160 | 0 | 0/100 | 190→135 | 0→0 |
| 스프레드시트 기본 | 80 | 0 | 0/100 | 190→105 | 0→0 |
| 인터넷 자료 활용 | 160 | 40 | 0/100 | 40→130 | 0→0 |
| 차트와 분석 | 80 | 80 | 0/100 | 80→110 | 30→20 |
| 컴퓨터 시스템 보호 | 160 | 160 | 100/0 | 30→30 | 160→185 |
| 컴퓨터 시스템 활용 | 80 | 80 | 100/0 | 20→30 | 170→105 |
| 페이지 설정과 인쇄 | 160 | 160 | 100/0 | 30→30 | 160→185 |
| 함수와 데이터 관리 | 80 | 80 | 100/0 | 20→30 | 80→105 |
| 합계 | 960 | 600 | — | 600→600 | 600→600 |

A의 추가 시간은 기존 [190,190,0,0]에서 **[135,105,90,30]**으로 분산됐다. 에이전트는 매크로를 학습했어도 0점인 교정 학습 대상으로 보고, 나머지 미보고 토픽은 실제 학습 여부를 단정하지 않고 개념·문제 학습을 배정했다. 1회 복습 예상은 네 토픽 모두 30분이며 전량 배치 가능해 15분 대안이 필요 없었다. 차트에 15분만 더한 중간 제안은 이 최소량에 미달하여 거절됐다.

B의 추가 시간은 기존 [0,90,0,0]에서 **[25,25,25,25]**로 분산됐다. 에이전트가 각 토픽의 1회 복습도 25분으로 제안했고 실제로 전량 배치 가능해 15분 대안을 사용하지 않았다. 이는 에이전트가 선택한 분량이다. 고득점 차트는 세 조건에 따라 20분 복습을 선택했다.

고득점 복습 예상량도 모델이 선택하므로 A의 순추가 풀은 380→360분, B는 90→100분으로 달라졌다. 모든 변화가 편중 방지 규칙만의 효과라는 주장은 하지 않는다. 비결정적 모델의 한 번의 유효한 실행이며 학습 효과의 최적성은 입증하지 않는다.

A는 4회, B는 3회 모델 요청 후 성공했다. 합산 오류·추가량 상한 초과·복습 최소량 미달 제안은 거절하고 최종 결과만 저장했다. 앞선 중간 정책 실행의 시간대 분할 실패는 성공으로 집계하지 않았다.

두 결과 모두 기존 시간대·보호 행·각 입력의 보고와 메타데이터를 보존하고 미리보기·저장·인증 GET 재조회·디스크 CSV가 일치했다. 신규 15분 미만 세션은 0개, 최소 세션은 모두 15분이다. 확인 저장에는 모델 재호출이 없다.

실제 증빙은 로컬 `backend/coverage-results/review-sized-balanced-live-validation.json` 및 `.log`, 현재 기본 테스트 캡처는 `backend/tests/schedule_adjuster_tests/fixtures/generated_plan_reassessment.json`이다. 이전 10분 보고 캡처는 역사 자료로 보존하고 변하지 않은 고득점 규칙·기록·시간대에 대해서만 검사한다. 그 과거 배분을 v5의 유효한 편중 방지 제안으로 취급하지 않는다. 이번 추가 요청에서는 기본 A/B만 실제 재실행했다.
