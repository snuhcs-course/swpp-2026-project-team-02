# 고득점 토픽의 에이전트 선택 1회 복습 (2026-11-28)

> 아래는 고득점 세 조건과 v2/v3 실행 이력이다. 현재는 세 조건을 유지하면서 취약 토픽 추가량·1회 복습 최소량·물리적 불가능 시 15분 대안을 보완한 [v5 검증](reassessment-balanced-additions.md)을 따른다. 테스트의 기본 실제 캡처도 v5로 갱신했으며 아래 과거 표의 재실행 결과를 뜻하지 않는다.

## 적용 규칙

사용자가 정정한 조건을 적용했다. 자격증 합격 점수를 P, 토픽 진단 점수를 S라 할 때 고득점 경계는 `H = min(P + 10, 100)`이다. **S >= H인 토픽에만** 다음 두 조건 중 하나라도 해당하면 1회 복습으로 감축한다.

1. 원본 토픽 전체 배분 T가 양수이고, 원본 변경 가능 잔여 R이 `T × 0.95` 이상이다.
2. 해당 토픽에 유효한 학습 보고가 하나 이상 있고, 보고한 실제 학습 시간의 합 A가 10분 이하이다.
3. 고득점이지만 위 두 조건에 해당하지 않으면 토픽별 감축 제한이나 최소 복습 하한이 없다. **0분까지 감축 가능**하며, 70~99점처럼 100점 미만인 고득점에도 같은 규칙을 적용한다. 구체적인 최종 분량은 에이전트가 결정한다.

합격 점수는 클라이언트 입력이 아니라 `backend/config/certifications.json`의 자격증별 `passing_score`에서 가져온다. 현재 지원하는 컴퓨터활용능력 2급은 필기 기준 60이므로 H=70이다. [대한상공회의소 공식 합격 기준](https://license.korcham.net/customer/faq.do?bigCate=15)은 필기 과목별 과락 조건과 평균 60점을 명시한다. 여기서 70점은 사용자가 지정한 토픽 감축 경계이며, 과목별 과락 판정이나 합격 예측을 구현한 것이 아니다. 새 자격증에 합격 점수가 없거나 숫자가 유효하지 않으면 재평가가 이를 임의의 값으로 대체하지 않는다.

T는 과거·진행 중·미래를 포함한 현재 원본 계획의 토픽 전체 분량이다. R은 기준 시각 이후 시작하고 보호되지 않은, 실제 변경 가능한 분량이다. T−R이 완료량이라는 뜻은 아니다. A는 현재 일정에 연결된 보고의 실제 분량 합이며 완료 처리로 인정한 계획 분량과 별개다. 보고가 전혀 없으면 A의 합산값이 0이어도 조건 2에서 제외한다. T=0인 신규 토픽은 조건 1에서 제외한다.

## 에이전트가 선택하는 시간과 검증

에이전트는 해당 토픽별로 `review_sessions`에 `{topic, minutes, reason}`을 제안한다. minutes는 토픽의 내용·원본 분량·진단·기록을 고려해 에이전트가 선택한 양의 정수이고, 실제 배정 목표는 **`max(minutes, 15)`**이다. 모든 토픽을 고정 15분으로 계산하는 함수는 없다.

백엔드는 각 대상 토픽에 대해 이 목표와 정확히 같은 총량의 연속된 복습 1회를 요구한다. 원본 행 경계가 달라도 시간상 맞닿아 있는 동일 토픽 조각은 연속 복습으로 간주한다. 떨어진 여러 시간대에 나눠 배정하거나 다른 추가 학습을 붙이면 거절한다. R>15이면 실제 목표가 R보다 작아야 한다. R<=15이면 15분 하한까지 늘 수 있으며, R=0이라도 조건 2를 충족한 고득점 토픽은 새 복습 1회를 배정한다.

조건 미충족 고득점 토픽은 0분도 허용하므로 필수 토픽 수·시간 사전 검사에서도 제외한다. 저득점(S<H) 토픽에는 미래 학습을 일부 배정해야 한다. 100점 미만 전체를 필수로 취급하던 기존 검사를 고득점 경계 H로 변경하여 3번과 충돌하지 않게 했다. 이전에 초기화한 50% 감축 제한·미완료 보존 하한·학습률 상대 우선순위 규칙은 복구하지 않았다. 정책 버전 `high-score-agent-review-v3`, 합격 점수, 경계, 보고와 적용 사유를 미리보기 서명 문맥에 넣어 이전 정책이나 다른 입력으로 미리보기를 저장할 수 없다.

기존 과거·진행 중·외부·보호 일정, 각 변경 대상 시간대와 총시간을 유지한다. 모든 토픽이 감축 대상이어서 줄인 시간을 배정할 곳이 없으면 `NOT_ENOUGH_TIME`으로 거절한다. 제안이 잘못되면 최대 4회 모델 요청 내 수정하며 실패한 제안은 저장하지 않는다. 확인 저장에는 모델을 다시 호출하지 않는다. 앱에는 모델 자유 서술 대신 서버가 작성한 사실 요약을 표시한다. Demo는 기존 로컬 시뮬레이션이며 이 규칙은 Live 백엔드에 적용한다.

## 같은 실제 생성 원본·기본 기록의 A/B 실행

아래 실제 A/B 실행 수치는 v2 당시 캡처다. 3번을 명시한 v3에서 새 모델을 호출해 생성한 수치는 아니며, 현재 검증기로 캡처 제안을 재생하여 여전히 유효함을 확인한다.

실제 모델로 생성해 캡처한 원본을 재사용했다. 전체 960분 중 과거·진행 중 360분은 고정하고 미래 600분을 바꾼다. 매크로 보고는 완료 120분·부분 완료 20분으로 실제 합 140분이다. 다른 토픽은 미보고이며 0분 보고로 간주하지 않는다. A는 앞 4개 토픽 0%·뒤 4개 100%, B는 반대다. 이번 재평가 제안은 실제 `google/gemini-2.5-flash` 호출 결과다.

| 토픽 | 원본 전체 | 원본 잔여 | A 점수 | A 재조정 잔여 | B 점수 | B 재조정 잔여 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 매크로 활용 | 160 | 0 | 0% | 75 | 100% | 0 |
| 스프레드시트 기본 | 80 | 0 | 0% | 65 | 100% | 0 |
| 인터넷 자료 활용 | 160 | 40 | 0% | 145 | 100% | 40 |
| 차트와 분석 | 80 | 80 | 0% | 255 | 100% | 30 |
| 컴퓨터 시스템 보호 | 160 | 160 | 100% | 15 | 0% | 210 |
| 컴퓨터 시스템 활용 | 80 | 80 | 100% | 15 | 0% | 80 |
| 페이지 설정과 인쇄 | 160 | 160 | 100% | 15 | 0% | 160 |
| 함수와 데이터 관리 | 80 | 80 | 100% | 15 | 0% | 80 |
| 합계 | 960 | 600 | — | 600 | — | 600 |

A의 뒤 4개는 고득점이고 R/T=100%여서 각각 15분 복습이 됐다. B에서는 차트만 고득점·R/T=100%여서 에이전트가 30분을 선택했다. B의 매크로는 A=140>10이고 R=0이므로 해당하지 않는다. 스프레드시트는 보고가 없고 R=0이므로 해당하지 않는다. 인터넷은 R/T=25%이고 보고가 없어 해당하지 않는다. 저득점 토픽에는 이 강제 감축을 적용하지 않았다.

기본 실행 A는 3회 요청 중 누락된 취약 토픽·불연속 복습 제안을 거절한 뒤 성공했고 B는 1회에 성공했다. 이에 앞선 공급자 오류 실행은 성공으로 집계하지 않았다. 결과는 모델의 한 번의 유효한 제안이며 반복 실행의 수치 동일성이나 학습 효과의 최적성을 주장하지 않는다.

## 실제 학습 10분 경계의 별도 실제 실행

같은 원본의 매크로 두 보고를 Partly 5분씩, 합계 10분으로 바꿨다. A/B 두 입력에서 이 기록은 동일하다. 매크로는 미래 잔여가 0이므로 조건 1에 해당하지 않아 조건 2의 점수 제한을 독립적으로 확인할 수 있다.

| 매크로 입력 | 진단 | 보고 합 | 복습 감축 대상 | 모델의 미래 배정 |
| --- | ---: | ---: | --- | ---: |
| A | 0% | 10분 | 제외 | 210분 |
| B | 100% | 10분 | 조건 2 적용 | 15분 |

A의 210분은 자유롭게 제안된 저득점 학습 분량이며 복습 상한이 아니다. B의 15분은 에이전트가 제안한 복습과 하한을 적용한 연속 복습이다. A/B 모두 서명 미리보기·저장·GET 재조회·디스크 CSV가 같고 모델 재호출 없이 저장됐다. 단, 고득점 여부 외에 A/B의 다른 토픽 점수도 다르므로 이 표를 매크로 점수만 바꾼 인과 실험이라고 주장하지 않는다. 고득점 69/70 경계와 자격증 합격 점수별 경계는 별도 통제 단위 테스트로 확인한다.

이 실행은 A/B 각각 2회 요청으로 성공했다. 원본 구간 합산 오류·복습 불연속 초기 제안은 거절했다. 네 결과 모두 새 15분 미만 세션 0개이며 기본 A/B 최소 세션 15/30분, 10분 보고 A/B는 15/15분이다. 각 입력의 기록, 과거·진행 중 일정, 미래 총 600분과 메타데이터를 보존했다.

## 규칙 3 추가 후 v3 검증

- 고득점이지만 조건 1·2 미충족인 70/80/99/100점 토픽에서 잔여 50분→0분을 허용한다. 합격 점수 80인 자격증의 90점에서도 동일하다. 미보고와 명시적 11분 보고를 모두 확인했다.
- 같은 토픽에서 에이전트의 15/20/35/50분 제안도 허용하여 특정 감축 비율이나 15분 복습량을 강제하지 않음을 검증했다. 저득점 69점의 누락, 고득점이면서 조건 1 또는 2에 해당하는 토픽의 0분 배정은 거절한다.
- 0분 배정 가능한 고득점 토픽을 필수 토픽 수에서 제외하여, 짧은 기존 구간만 남았을 때도 불필요한 용량 부족 오류가 발생하지 않음을 확인했다. 원본 시간대·총시간·보호 일정과 기존 세션 분할 제약은 계속 적용한다.
- Linux 백엔드 전체 **530개 통과**, 건너뜀 0(계획 생성 151·일정 조정 108·API 271).
- Windows 일정 조정 **108개 통과**, API **264개 통과·기존 권한 관련 7개 건너뜀**, 실패 0. 이 7개도 위 Linux 전체 실행에서는 통과했다.
- 기존 실제 A/B 및 10분 보고 캡처를 현재 검증기로 재생하여 통과했다. 이 회귀 검증 시점에는 v3 모델을 새로 호출하지 않았다. 이후 사용자가 요청한 실제 재실행은 아래에 별도로 기록한다. Android 제품 코드는 변경하지 않았다.
