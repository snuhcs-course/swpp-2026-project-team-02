## 실패 분석

### 1. 진단과 무관하게 '함수와 데이터 관리'에 시간이 몰림 (T5 미달의 원인)

- 성공한 96회 중 **78회(81%)**에서 '함수와 데이터 관리'가 가장 많은 시간을 받았습니다.
- 전부 정답(A01)과 전부 오답(A02)은 진단상 차이가 없는데도 비율이 각각 약 15:50:35, 18:50:32(기본:함수:차트)였습니다. 진단과 별개로 고정된 우선순위가 있다는 뜻입니다.
- HE 사례 답안(차트 0점, 함수 50점, 기본 100점)으로 만든 64회의 평균 비율은 기본 11% : 함수 47% : 차트 42%로, 가장 약한 차트보다 함수가 더 많았습니다.
- '스프레드시트 기본'만 약한 A05는 3회 모두 기본이 가장 적은 시간을 받았습니다(상관계수 +0.75~+0.87, 기준과 반대 방향).
- 그룹별 T5 통과율: A 18/24, B 12/23, C 4/18, D 5/6, E 2/14, F 3/6. 약속이 있거나(C) 계획이 긴 경우(E) 특히 낮습니다.
- **추정 원인:** 계획 Agent는 문항을 토픽에 직접 다시 분류하고 시간을 정합니다. 이때 모델이 시험에서 함수 비중이 크다는 자체 판단을 진단 점수보다 우선하는 것으로 보입니다. 이번 실행은 `tool_calls`를 저장하지 않아 분류 결과는 확인하지 못했습니다. P31에서 확인합니다.

### 2. 간헐적 생성 실패 (502 UPSTREAM_ERROR, 3/105)

- A01 #3, B02 #1, E02 #2에서 22~30초 뒤 "Study plan generation failed"가 났습니다.
- 같은 사례의 다른 회차는 모두 성공해서, 입력 문제가 아니라 모델이나 Agent의 간헐적 실패로 보입니다.
- 앱은 이 경우 오류와 '다시 시도'를 보여 주므로 사용자는 복구할 수 있습니다(10/31 실기기 검증 과제 4).

### 3. 조정한 일정이 시험 이후로 밀림 (4/14)

- 조정 규칙(같은 토픽의 다음 일정 뒤 첫 빈 시간)은 모두 지켰지만(J2~J5 14/14), 4회는 옮긴 일정이 시험 시각 뒤에 놓였습니다.
- 조정 API가 시험일을 모르기 때문이며, 사용자에게는 쓸모없는 일정이 됩니다. US-C3·C4 관점에서 개선이 필요합니다.

### 4. 짧은 일정과 낮은 활용률

- 15분 미만 일정 비율이 평균 20.8%로 목표 10%를 넘었습니다. 10/31 실기기 검증의 '매일 5분 일정'과 같은 현상입니다.
- 활용률 중앙값은 52.6%로 목표는 넘었지만, 3회 중 1회꼴로 가용 시간의 절반도 쓰지 않았습니다.

### 5. 자기 평가 문장의 영향

- 진단과 반대되는 자기 평가(F02, "차트는 자신 있음")에서는 차트가 최다 시간을 받은 경우가 1/3뿐이고 상관계수도 0.0~−0.5로 약해졌습니다. 문장이 진단 점수보다 크게 반영될 수 있습니다.

### 정상 동작 확인

- 가용 시간, 준비 기간, 약속과의 겹침 위반은 200 응답 96회 전부에서 없었습니다(T2).
- 가용 0분(D01, D02)과 날짜 오류(D06)는 모델 호출 없이 즉시 422로 거절됐습니다.
- 가용 2분(D03)은 3회 모두 "2분이라 … 최소 1분씩 배정할 수 없어요"라는 NOT_ENOUGH_TIME 안내로 거절됐습니다.

## P31로 넘길 개선점

1. 토픽별 시간 비율을 진단 점수에서 직접 계산해 Agent에 주거나, Agent 결과가 약점 순서와 맞는지 검증하는 단계를 추가합니다 (T5 대응).
2. 생성 응답의 `tool_calls`를 저장해 문항–토픽 분류와 배분 근거를 확인합니다.
3. 최소 공부 단위(예: 15분)를 정해 짧은 일정을 합칩니다.
4. 조정 요청에 시험일을 넘겨, 시험 이후로 밀리지 않게 합니다.
5. 같은 기준으로 다시 실행해 T5와 보고용 지표를 비교합니다.
